# ADR-002 – Authentication & Authorization Architecture for Backoffice and E-Commerce

**Status:** Accepted

## Context
- The application needs an authentication system for two purposes:
  1. Administrative backoffice access for Pablo Valdés to manage received leads, review marketing prospects, and manage services.
  2. Future client access for the upcoming multi-product digital store and SaaS rentals.
- In accordance with the project specification and ADR-001, any authentication system must be simple, secure, testable, and maintainable within the existing monolithic modular architecture.

## Decision
- **Algorithm & Token Mechanism:** JSON Web Tokens (JWT) signed with HMAC-SHA256 (`HS256`) with a configurable secret key (`SECRET_KEY`) and expiration time (default: 24 hours).
- **Password Hashing:** Cryptographic PBKDF2 with HMAC-SHA256 and unique random salt per user (using Python standard library `hashlib` to avoid complex native binary compilation dependencies on Windows/Linux containers).
- **Database Model:** Table `users` in PostgreSQL:
  - `id SERIAL PRIMARY KEY`
  - `email VARCHAR(255) UNIQUE NOT NULL`
  - `password_hash VARCHAR(255) NOT NULL`
  - `salt VARCHAR(64) NOT NULL`
  - `full_name VARCHAR(150) NOT NULL`
  - `role VARCHAR(50) NOT NULL DEFAULT 'client'` ('admin', 'client')
  - `is_active BOOLEAN NOT NULL DEFAULT true`
  - `created_at TIMESTAMPTZ NOT NULL DEFAULT now()`
- **Endpoints in API:**
  - `POST /auth/login` → Authenticates credentials, returns JWT bearer token and user profile.
  - `GET /auth/me` → Returns currently authenticated user context based on Bearer token.
- **Frontend View:**
  - Route `/login` in `apps/web/src/app/login/page.tsx` adhering to the dark obsidian and wine-red design system.

## Consequences
- **Positive:**
  - Zero external auth vendor lock-in (Firebase/Auth0).
  - Reproducible across Docker containers and testable in CI with `pytest`.
  - Ready for immediate backoffice lead administration and future multi-product checkout.
- **Negative:**
  - Requires maintaining user revocation policies as token volumes grow (mitigated via short expiration times).
