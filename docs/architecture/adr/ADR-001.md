# ADR-001 – Adopt a monolithic FastAPI backend

**Status:** Proposed

## Context
- The specification (ESPECIFICACION_MAESTRA_SOFTWARE.md) directs us to start with a simple, scalable monolith.
- No authentication, ecommerce, micro‑services, or complex infrastructure is allowed without an ADR.
- A FastAPI monolith satisfies the requirement for a clean, testable backend while keeping the stack minimal.

## Decision
- Use a single FastAPI application (`apps/api/main.py`) exposing health endpoints.
- Deploy the API together with PostgreSQL via Docker Compose.
- Future features (e.g., contact‑lead API, frontend) will be added to this monolith.

## Consequences
- **Positive**: Simpler local development, fewer moving parts, easy to test.
- **Negative**: As the project grows, the monolith may need to be split; this will be addressed in later ADRs.

## Alternatives considered
- Multi‑service architecture (Kubernetes, separate auth service) – rejected due to spec constraints.
- Serverless functions – rejected for lack of Docker‑based reproducibility.
